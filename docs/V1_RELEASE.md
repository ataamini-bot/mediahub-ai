## بستن انتشار، پس از پذیرش مالک

1. کد و چهار راهنمای زبان را در `develop` با **merge commit** ادغام کن. از squash یا rebase که نسب نسخهٔ نصب‌شده را قطع کند استفاده نکن؛ کنسول Update فقط نسخه‌ای را می‌پذیرد که از commit فعلی جلوتر باشد. پیش از تگ، روی SHA نهایی موفقیت CI و این دستور را بررسی کن:
   `git merge-base --is-ancestor 16775b765c501e3afe2ad18eff8fb86afd6c0743 HEAD`.
2. در تغییر انتشار، `release.json.version` را از `v1.0.0-rc.1` به `v1.0.0` تغییر بده. مقدار schema باید با تنها head در Alembic یکی باشد. شناسهٔ نهایی و نتیجهٔ تست را ثبت کن. تا پیش از موفقیت انتشار Imageها، راهنماهای عمومی روی SHA نامزدِ آزموده بمانند.
3. فقط پس از تأیید مالک، تگ `v1.0.0` را روی همان commit موفق ایجاد کن. workflow تگ تست و ساخت سه Image را اجرا می‌کند. نتیجهٔ **Verify public install images** باید `PUBLIC_IMAGES=OK` باشد؛ بازبینی معادل روی یک میزبان مجزا با Docker، در checkout همان تگ: `python3 scripts/verify_release_images.py v1.0.0`. اگر مخزن بسته‌ها خصوصی باشد، مالک visibility را بررسی و فقط مرحلهٔ ناموفق را دوباره اجرا کند.
4. با همان تگ روی Ubuntu آزمایشی تازه، نصب تا Start ربات و سلامت سرویس‌ها را بررسی کن. سپس [یادداشت انتشار آماده](releases/v1.0.0.md) را برای GitHub Release به‌کار ببر و در راهنماهای چهارزبانهٔ شاخهٔ پیش‌فرض، دستور نصب را از SHA نامزد به تگ رسمی تغییر بده. وجود تگ به‌تنهایی نشانهٔ آماده‌بودن نصب عمومی نیست.
